tmux 실습 가이드

터미널(Ghostty·iTerm) 분할 vs tmux 차이를 손으로 확인하고, 세션 개념을 몸으로 잡는 두 실습.

💡 이 가이드는 Ghostty와 iTerm2 둘 다에서 됩니다. 분할 단축키가 동일해요 — ⌘ D 좌우 · ⌘ ⇧ D 상하 · ⌘ W 닫기 · 칸 이동 ⌘ [ ⌘ ]. (iTerm2는 칸 이동에 ⌘ ⌥ 방향키도 됩니다.) 아래에서 "터미널"은 본인이 쓰는 쪽으로 읽으세요.

실습 A터미널(Ghostty·iTerm) 분할 vs tmux — 뭐가 다른지 직접 본다

"눈으로 3개 보기"는 똑같다. 차이는 창을 닫았을 때 드러난다.

A-1. 터미널 분할(Ghostty·iTerm) — 창 닫으면 다 죽는다

1

터미널(Ghostty/iTerm)에서 화면을 좌우로 분할

⌘ D 좌우 분할 · ⌘ ⇧ D 상하 분할 · 칸 이동 ⌘ [ ⌘ ] (iTerm2는 ⌘ ⌥ 방향키도)

2

한쪽 칸에서 긴 작업을 흉내

# 왼쪽 칸에서
ping localhost

계속 출력되는 걸 둔 채로 다음 단계로.

3

터미널 창을 그냥 닫는다 (⌘W)

그리고 새 터미널 창을 연다.

😵 결과: 아까 그 ping은 사라졌다. 다시 볼 방법이 없다. 창에 매달려 있던 세션이 창과 함께 죽었기 때문.

A-2. tmux — 창을 닫아도 살아있다

1

tmux 세션 시작

tmux new -s test

2

같은 긴 작업을 흉내

ping localhost

3

터미널 창을 그냥 닫는다 (⌘W) — A-1과 똑같이

새 터미널 창을 연 다음, 다시 붙는다:

tmux attach -t test
🎉 결과: ping이 그대로 돌고 있다. 창은 죽었지만 세션은 tmux 서버가 들고 있었다. 이게 터미널 분할로는 절대 안 되는 일.
⚙️ 정리: exit 두 번 입력하거나, 세션 밖에서 tmux kill-session -t test

한눈에

터미널 분할(Ghostty·iTerm)tmux
동시에 여러 개 보기✅✅
창 닫아도 안 죽음❌✅
나중에 다시 붙기❌✅
원격 서버에서 유지❌✅

터미널 분할 = 그림. tmux = 창 밖 별도 서버가 작업장을 들고 있음.

실습 Btmux 세션 개념 잡기 (detach / attach / 여러 세션)

세션 = 창에서 떼어내 서버에 맡긴 "작업장". 떼었다(detach) 붙였다(attach) 하는 감각을 익힌다.

B-1. detach / attach — 핵심 중 핵심 (3번 반복하세요)

1

이름 붙여 세션 시작

tmux new -s work

2

안에서 뭔가 실행

top

3

detach — 작업장에서 빠져나오기 (죽이는 게 아님)

Ctrl b 를 누르고 손 뗀 뒤 d

4

밖에서 살아있는 세션 확인

tmux ls

→ work 세션이 백그라운드에 살아있음

5

다시 붙기

tmux attach -t work
느낄 점: 나왔다 들어가도 top이 계속 돌고 있다. 빠져나오는 것(detach) ≠ 끄는 것. SSH 끊김도 똑같이 detach일 뿐이다.

B-2. 세션 여러 개 — 작업 단위로 분리

1

세션 두 개를 만들고 각각 빠져나오기

tmux new -s server      # 만든 뒤 Ctrl b 그리고 d
tmux new -s logs        # 만든 뒤 Ctrl b 그리고 d

2

목록 보고 골라 들어가기

tmux ls                 # server, logs 두 개 보임
tmux attach -t server

3

세션 안에서 다른 세션으로 전환

Ctrl b 그리고 s → 화살표로 골라 Enter

느낄 점: 세션 = 독립된 작업 공간. 프로젝트마다 하나씩 두면 머릿속이 정리된다.

B-3. 정리하기

tmux kill-session -t logs   # 특정 세션만 종료
tmux kill-server            # 전부 종료

멘탈 모델

세션은 백그라운드에서 도는 "작업장"

attach/detach = 그 작업장에 들어갔다 나왔다 하는 것. 창은 그저 잠깐 붙는 뷰어일 뿐, 작업장은 tmux 서버가 들고 있다.

추천 순서: B-1을 3번 반복해서 detach/attach가 손에 붙으면, 나머지는 금방입니다.

실습 C한쪽 페인에서 다른 쪽으로 "말 걸기"가 되나?

두 칸에 각각 CLI를 띄워놓고, 한 칸에서 옆 칸으로 메시지를 보낼 수 있나를 직접 친다. 이게 tmux와 일반 에뮬레이터의 진짜 차이.

C-1. 터미널 2분할(Ghostty·iTerm) — 옆 칸을 부를 방법이 없다

1

터미널(Ghostty/iTerm)을 좌우로 분할 (⌘D)

왼쪽·오른쪽 두 칸이 생긴다.

2

오른쪽 칸에서 메시지를 기다리는 CLI 하나 띄우기

# 오른쪽 칸에서 — 입력을 그대로 받아 보여주는 간단한 CLI
cat

이제 오른쪽은 "입력을 기다리는 상대"다.

3

왼쪽 칸에서 오른쪽 칸으로 글자를 보내보기

…그런데 보낼 명령이 없다. Ghostty·iTerm 같은 에뮬레이터엔 "옆 칸에 글자를 넣어라" 같은 게 없다. 왼쪽 칸은 오른쪽 칸의 존재도, 주소도 모른다.

🚫 결과: 직접 마우스로 오른쪽 칸을 클릭해서 타이핑하는 것 말곤 방법이 없다. 칸끼리는 서로를 부를 수 없다 — 그냥 나란히 그려진 그림일 뿐.

C-2. tmux 2분할 — 주소로 옆 칸에 글자를 꽂는다

1

tmux 세션 만들고 좌우 분할

tmux new -s talk

그 안에서 Ctrl b 그리고 % → 왼쪽=페인 0, 오른쪽=페인 1

2

오른쪽 칸(페인 1)에서 메시지를 기다리는 CLI 띄우기

오른쪽 칸을 클릭하고:

cat

→ C-1과 똑같이 "입력을 기다리는 상대". 이제 왼쪽으로 돌아간다.

3

왼쪽 칸(페인 0)에서 — 오른쪽 칸 주소로 메시지 전송

tmux send-keys -t 1 '안녕! 0번 페인이 보낸 메시지야' Enter

-t 1 = "1번 페인에게". 글자를 거기 타이핑해 넣고 Enter까지 눌러준다.

🎉 결과: 손 안 댄 오른쪽 칸에 그 메시지가 나타난다 (cat이 받아서 그대로 출력). 왼쪽 칸이 오른쪽 칸에 말을 건 것. 가능한 이유는 단 하나 — tmux 서버가 페인마다 주소(0, 1)를 달아 관리하기 때문.
⚠️ -t 1에서 에러 나면 페인 번호가 다른 것 — tmux list-panes로 번호 확인 후 그 번호로. 정리는 양쪽에 Ctrl c 후 exit.

(선택) 옆 칸의 CLI에 진짜로 말 걸기

cat 대신 오른쪽 칸에 claude나 opencode 같은 CLI를 띄워도 똑같다. 왼쪽에서 tmux send-keys -t 1 '질문...' Enter 하면 그 CLI가 질문을 받아 답한다. 이게 Claude Code의 Agent Teams가 팀메이트(다른 모델 CLI)와 통신하는 원리 — tmux 주소로 메시지를 꽂는 것이다.

한눈에

터미널 2분할(Ghostty·iTerm)tmux 2분할
두 칸에 CLI 띄우기✅✅
옆 칸 주소가 있나❌ 없음✅ 0, 1…
한 칸 → 옆 칸 메시지❌ 불가✅ send-keys

실습 A·B·C를 관통하는 한 문장

tmux는 작업장을 창 밖 별도 서버에, 주소를 달아 둔다. 그래서 ① 창을 닫아도 안 죽고(A·B) ② 그 주소로 칸끼리 메시지를 주고받을 수 있다(C). 일반 에뮬레이터엔 둘 다 없다 — 그냥 화면을 그릴 뿐.
